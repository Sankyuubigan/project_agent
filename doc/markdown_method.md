# Инструкция: метод правок «Умный Markdown» (v2)

В своём ответе присылай все изменения в формате ниже. Это единственный принимаемый формат правок.

## 1. Блок файла

```
<<<FILE: относительный/путь/к/файлу>>>
(полное новое содержимое файла)
<<<END_FILE: относительный/путь/к/файлу>>>
```

- Начало файла — тег `<<<FILE: путь>>>`. Путь — ОТНОСИТЕЛЬНЫЙ от корня проекта, прямые слэши (`/`) даже в Windows. Пример: `<<<FILE: src/app.py>>>`.
- Конец файла — тег `<<<END_FILE: тот же самый путь>>>`. Путь в закрывающем теге ОБЯЗАТЕЛЕН и должен совпадать с открывающим. Тег `<<<END_FILE>>>` без пути блок НЕ закрывает — он считается частью содержимого (защита от самоссылок), поэтому всегда указывай путь.
- Мы уже находимся в папке корня проекта.
- Текст вне блоков FILE…END_FILE полностью игнорируется программой — можешь писать там пояснения.

## 2. Целиком или точечно (SEARCH/REPLACE)

Выбирай способ изменения по размеру файла:

- **Файл новый, маленький (меньше 120 строк) или переписан больше чем наполовину** — присылай файл ЦЕЛИКОМ (содержимое между тегами = полный новый текст файла).
- **Точечная правка большого файла** — используй блоки SEARCH/REPLACE внутри блока файла:

```
<<<FILE: src/app.py>>>
<<<<<<< SEARCH
(точный фрагмент, который нужно найти в текущем файле)
=======
(новый фрагмент на его место)
>>>>>>> REPLACE
<<<<<<< SEARCH
(второй фрагмент)
=======
(его замена)
>>>>>>> REPLACE
<<<END_FILE: src/app.py>>>
```

Правила SEARCH/REPLACE:
- SEARCH должен совпадать с текущим текстом файла дословно, включая отступы. Бери фрагмент ПОБОЛЬШЕ — с несколькими окружающими строками, чтобы он встречался в файле ровно один раз.
- Если SEARCH не найден или встречается больше одного раза — правка будет отклонена целиком, файл не изменится. Не угадывай текст: точный фрагмент бери из присланного тебе кода.
- Можно несколько пар SEARCH/REPLACE подряд в одном блоке файла.
- SEARCH/REPLACE применяются только к СУЩЕСТВУЮЩИМ файлам. Новый файл создавай всегда целиком.

## 3. Удаление файла

Удаляй файл ТОЛЬКО отдельным тегом-строкой:

```
<<<DELETE_FILE: относительный/путь/к/файлу>>>
```

- НИКОГДА не «удаляй» файл, присылая его пустым: пустое содержимое между FILE…END_FILE означает «создать пустой файл», а не удалить.
- Удаляй файл только если это правда нужно по задаче (и не забудь убрать ссылки на него в других файлах).

## 4. Общие правила

- В ответе должны быть ТОЛЬКО изменённые файлы (создание, изменение, удаление). Файлы, присланные тебе для контекста без изменений, НЕ включай.
- Несколько файлов — просто повторяй структуру блоков друг за другом.
- Для файлов старайся не превышать 500 строк: разделяй логику на другие файлы, можешь создавать новые. Если присланный тебе файл больше 500 строк, при правках можешь разделить его.
- Не оборачивай блоки тегов в ``` без необходимости: если оборачиваешь, то пара ``` должна охватывать блок целиком (от `<<<FILE:` до `<<<END_FILE: путь>>>`).
- Содержимое файла — UTF-8, переводы строк LF. CRLF пришлётся-применится нормально, но не смешивай.

## 5. Примеры

Новый файл целиком:

```
<<<FILE: src/utils/hash.py>>>
import hashlib

def file_hash(path: str) -> str:
    return hashlib.sha256(open(path, "rb").read()).hexdigest()
<<<END_FILE: src/utils/hash.py>>>
```

Точечная правка существующего файла:

```
<<<FILE: src/app.py>>>
<<<<<<< SEARCH
def run():
    print("Running the new version!")
=======
def run():
    print("Running version 2!")
    log.info("started")
>>>>>>> REPLACE
<<<END_FILE: src/app.py>>>
```

Удаление файла:

```
<<<DELETE_FILE: src/old_module.py>>>
```

Создание пустого файла (редко, но валидно):

```
<<<FILE: .gitkeep>>>
<<<END_FILE: .gitkeep>>>
```
